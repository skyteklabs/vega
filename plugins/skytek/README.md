# skytek

Writes a Scope of Work (SOW) from an RFP or a short interview, fills it into one Word template, and delivers it as `.docx` and `.pdf`.

```sh
/plugin install skytek --marketplace skyteklabs/vega
/skytek:create-sow ~/Downloads/acme-rfp.pdf
```

Claude also picks the skill up on its own when you ask for an SOW or hand it an RFP.

## How it works

It is a skill plugin (`skills/create-sow/SKILL.md`), with no hooks:

1. **Read the input.**
   - PDF, txt and md: read directly.
   - docx: `scripts/extract_docx.py`, which keeps table rows.
   - `.doc`, `.rtf` and `.odt`: `textutil` on macOS.
   - A saved `.sow.json`: skips straight to rendering.
2. **Map** the RFP onto the fields in `assets/sow.schema.json`, recording each field's source (`rfp`, `inferred`, `default`, `user`).
3. **Interview** only for required fields the RFP left open. Pricing, payment and legal terms are never guessed.
4. **Review**: you approve a table of every value before anything is written.
5. **Render** with `scripts/render_sow.py`:
   - validates the JSON against the schema;
   - fills the template with [docxtpl](https://docxtpl.readthedocs.io);
   - converts the docx to PDF with LibreOffice (headless), or with Microsoft Word through docx2pdf.

   With neither installed, you get the `.docx` and the skill offers to install LibreOffice. It installs nothing without a yes.

Output goes to `outputDir` as `SOW_<client>_<project>_<date>_v<N>.{docx,pdf,sow.json}`. Files are never overwritten. Re-running on a `.sow.json` (edit it first if you like) gives the next `v<N>`.

Scripts run with [`uv`](https://docs.astral.sh/uv/) and declare their own dependencies (PEP 723). `uv` is the only requirement.

## The template

`assets/sow-template.docx` is generated by `scripts/build_template.py`. Its section layout follows Google's DAF/PSF partner SOW template, minus the Google funding text:

1. Executive Summary (overview, objectives, vendor and client overviews)
2. Requirements and Solution Overview (functional, non-functional, architecture)
3. Activities (one subsection per phase, with tasks)
4. Deliverables (by phase, with format; acceptance criteria)
5. Out of Scope, Assumptions and Risks (plus change control)
6. Success Criteria
7. Estimated Timeline
8. Project Roles (vendor and client)
9. Costs (package items or effort in mandays, extra fees, payment milestones, expenses, taxes)
10. Acceptance (signatures)

The cover and the header on later pages carry the SkyTek logo, next to a labelled placeholder for the client's. The builder rasterises the SkyTek logo from `assets/skytek-logo.svg`, because a Word template made with python-docx can't embed SVG, and reuses it as a watermark, turned 45° at 20% opacity, anchored behind the text of every page. After changing the layout or the logo, rebuild:

```sh
uv run skills/create-sow/scripts/build_template.py
```

Page and type:

- A4 with 1in margins. Table column widths fit the 6.27in text column.
- Body text is TWK Lausanne 300 at 11pt, justified. Table header rows and bold labels use TWK Lausanne 550, not synthetic bold.
- Headings are TWK Everett: Black for the cover title, Bold for section headings, Medium for subsections.

The builder ends by running `scripts/embed_fonts.py`, which embeds those five faces into the `.docx` (ECMA-376 obfuscated fonts), so Word and LibreOffice render them on machines without the fonts installed. Only the five `.otf` files in `assets/fonts/` that the template uses are committed; `.gitignore` keeps the rest of the families local. To change a weight, change the font name in `build_template.py`, add the face to `FONT_FILES` in `embed_fonts.py` and to the `.gitignore` allow-list, then rebuild. A font name with no `FONT_FILES` entry is not embedded and falls back to a substitute font. `build_template.py --no-embed-fonts` skips embedding, and `embed_fonts.py [path.docx]` embeds into an existing template.

To use a different template, either replace that file and run the check below, or point `templatePath` at your own file.

Template rules (docxtpl):

- `{{ field }}` prints a value. Type each tag in one go, or paste it as plain text. Word splits a tag that is edited halfway or formatted unevenly, and docxtpl then can't read it.
- Bullet lists repeat a paragraph: `{%p for item in objectives %}`, then a `{{ item }}` paragraph, then `{%p endfor %}`, each on its own line.
- Table rows repeat with `{%tr for d in deliverables %}` and `{%tr endfor %}`, each in its own row above and below the data row.
- Optional blocks use `{%p if roles %}` … `{%p else %}` … `{%p endif %}`.
- Dates, money and the pricing-model label arrive already formatted. Text with line breaks keeps them.

After any template edit, check that its fields match the schema exactly:

```sh
uv run skills/create-sow/scripts/render_sow.py --check-template [--template path.docx]
```

### Fields

`sow.schema.json` is the source of truth: each field's type, whether it's required, its meaning, and the interview question. Fields used by the template:

| Section | Fields |
|---|---|
| Cover and preamble | `project_title`, `client_name`, `client_address`, `vendor_name`, `vendor_address`, `sow_date`, `version`, `author`, `client_logo_path` (PNG/JPG; empty shows a placeholder), `msa_reference`, `governing_law` |
| 1. Executive Summary | `executive_summary`, `objectives[]`, `vendor_overview`, `client_overview` |
| 2. Requirements | `functional_requirements[]`, `non_functional_requirements[]`, `architecture_overview`, `architecture_components[]` (`name`, `description`), `integrations[]` (`name`, `description`) |
| 3. Activities | `phases[]` (`name`, `focus`, `tasks[]`) |
| 4. Deliverables | `deliverables[]` (`phase`, `name`, `description`, `format`), `acceptance_criteria` |
| 5. Scope, assumptions, risks | `out_of_scope[]`, `assumptions[]` (omitted means the standard list), `risks[]` (`risk`, `mitigation`), `change_control` |
| 6. Success Criteria | `success_criteria[]` |
| 7. Timeline | `start_date`, `end_date`, `timeline[]` (`phase`, `period`, `activities`) |
| 8. Roles | `vendor_roles[]`, `client_roles[]` (`role`, `responsibilities`) |
| 9. Costs | `project_type`, `currency`, `pricing_model`, `package_items[]` (`item`, `description`, `quantity`, `unit_price`) or `effort[]` (`role`, `mandays`, `day_rate`), `fees[]` (`item`, `amount`; negative for a discount), `subtotal`, `total_fees`, `total_mandays` (computed), `payment_schedule[]` (`milestone`, `deliverables`, `due`, `amount`), `payment_terms`, `expenses`, `tax_treatment` |
| 10. Acceptance | `vendor_signatory_name`, `vendor_signatory_title`, `client_signatory_name`, `client_signatory_title` |

Older `.sow.json` files fail validation:
- 0.1.0: `background`, `in_scope`, `milestones` and `roles` were replaced; move their values into the new fields.
- 0.2.0: add `project_type`, and move the priced lines out of `fees` into `package_items` or `effort`.

`project_type` picks the pricing table: `package` needs `package_items` and shows no mandays; `professional_services` needs `effort`. The schema rejects the wrong list for the type.

`_sources` is kept in the `.sow.json` and never rendered.

## Options

| Option | Default | What it does |
| --- | --- | --- |
| `outputDir` | `./sow` | Where the files are written |
| `templatePath` | (bundled) | Your own docxtpl template |
| `vendorName` | `SkyTek Labs` | Vendor on the cover, footer and signature block |
| `vendorAddress`, `vendorSignatoryName`, `vendorSignatoryTitle`, `vendorOverview` | empty | Vendor defaults; when empty, the skill asks |

Fees, mandays and rates aside, `client_logo_path` is the one field worth asking for even though the schema doesn't require it: if the client sent a logo file, pass its path so the cover uses it instead of the placeholder.

## Tests

`tests/test_render.py` covers:
- rendering `assets/sample.json`;
- that the template's fields match the schema, including a freshly built one;
- no tags left in the output;
- formatting of dates, money, escaping and line breaks;
- fallbacks for optional fields and empty lists;
- the client-logo placeholder, embedding a given logo, and rejecting a missing or unreadable one;
- package and effort pricing, and rejecting pricing that doesn't match `project_type`;
- discount lines and rejecting a negative total;
- versioned file names;
- rejecting invalid data;
- reading docx tables back.

PDF conversion is tested only when LibreOffice is installed.

```sh
uv run --with pytest pytest plugins/skytek/tests
```
